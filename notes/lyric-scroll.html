给播放器写歌词滚动的一晚上

看起来只有三行字的歌词窗，写起来比整张卡片都费劲。

当前唱到哪一句

最直觉的写法是正着遍历：从第一句开始，找到最后一个时间小于等于当前播放位置的。逻辑没错，但每次都要从头走一遍。

真正在 MusicPlayer.vue 里用的是反向遍历：

ts
const currentIndex = computed(() => {
  const list = lyrics.value
  const t = currentTime.value
  for (let i = list.length - 1; i >= 0; i--) {
    if (list[i].time <= t) return i
  }
  return -1
})

从末句往前找，第一条满足 time <= 当前时间 的就是答案，可以立刻返回。因为绝大多数时候当前句都靠近数组尾部，反向找通常两步就命中了。

返回 -1 那个分支是给前奏留的：当前时间还没到第一句的时间戳，就返回 -1，界面显示「前奏 · · ·」。这一支必须单独处理，不然上一句和下一句的取值会落到数组外面去。

取值的部分也没敢直接写 list[i]，而是包了一层带边界检查的函数：

ts
function lineAt(index: number): string {
  const list = lyrics.value
  return index >= 0 && index < list.length ? list[index].text : ''
}

有了它，上一句和下一句就可以放心地写成 lineAt(currentIndex - 1) 和 lineAt(currentIndex + 1)——前奏时上一句是空的，末句之后下一句也是空的。

mode="out-in" 带来的高度塌陷

三行歌词各自包在一个 <Transition name="lyric" mode="out-in"> 里，做淡出淡入的切换。

out-in 的意思是：旧元素完全走完退场动画，新元素才开始进场。问题就在这个空档里——那几十毫秒内，容器里是没有内容的。歌词行的高度本来由文字撑开，字一没了，高度就归零，整张卡片会跟着抖一下。

修法很土：别让容器的高度由内容决定。

css
.lyric-slot {
  display: grid;
  place-items: center start;
  height: 22px;
  overflow: hidden;
}

.lyric-slot--current {
  height: 30px;
}

上一句、下一句固定 22px，当前句固定 30px，外面再补一个 min-height: 76px 的窗户。高度全程不动，动画就只剩透明度在变。文字长了也不怕——overflow: hidden 加 text-overflow: ellipsis，截断就是了。

timeupdate 只有 4Hz

播放进度条的第一版是用 <audio> 的 timeupdate 事件驱动的。能用，但一眼就能看出不对：进度条是一跳一跳往前走的。

原因是这个事件的触发频率由浏览器定，大约每秒四次。对歌词来说够用；对一根几百像素长的进度条来说，四分之一秒一跳就太粗了。

于是播放期间改用一个 requestAnimationFrame 循环直接读 el.currentTime：

ts
function tick() {
  syncTime()
  rafId = requestAnimationFrame(tick)
}

rAF 跟着屏幕刷新率走，一般每秒六十次，进度条就顺了。关键是什么时候停：onPlay 里启动，onPause、onEnded 和 onBeforeUnmount 里都必须取消，否则暂停之后它还在后台空转，一路烧电。

拖动进度条时另有一个小坑：timeupdate 会和你拖出来的值打架，于是多了一个 isSeeking 标志——拖动中显示 seekValue，松手（change 事件）才写回 currentTime，两边不互相覆盖。

只能有一个在响

首页和弦歌台都会挂好几张播放卡片。如果每张各自为政，点第二首时第一首还在唱。

办法是把当前活跃的音频元素放到模块作用域，而不是组件内部：

ts
let activeAudio: HTMLAudioElement | null = null

放在模块里，同一个页面上的所有实例才共享得到它。点播放时先掐掉上一个，再播自己：

ts
function ensureSinglePlayer(el: HTMLAudioElement) {
  // 活跃元素就是自己时直接返回
  if (activeAudio === el) return
  if (activeAudio) activeAudio.pause()
  activeAudio = el
}

这段判断的要点只有两条：同一张卡片重复点击时，活跃元素就是自己，直接返回；否则先掐掉上一个，再把自己记成活跃元素。组件里是等价的紧凑写法，这里展开成函数，只为把两条分支说清楚。

onBeforeUnmount 里还要多做一步：暂停自己，并且如果自己就是那个活跃元素，把引用清成 null，免得留下一个指向已销毁节点的悬空引用。

小结

这一晚的时间大多没花在功能上，而是花在两个看不见的地方：动画切换中间那几十毫秒的空白，和事件频率够不够密。功能能跑只算一半，另一半是不抖、不卡、不互相打架。
