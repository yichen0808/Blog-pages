把首页写成组件，而不是配置

配置能给你的，是它能想到的版式；想不到的那部分，只能自己写。

layout: home 为什么不够

VitePress 自带的首页布局很好用：填几段文字，配几个 features，一分钟就能出一屏。但它本质上是一套已经拼好的积木——头像、标题、标语、按钮，位置和层数都定死了。

我想要的是一块能压住整屏的横幅：头像带一圈缓慢旋转的描金环，背景图在背后极慢地漂移，四角有一点点描金的窗棂。这些在配置里没有对应的字段，硬凑只会凑出四不像。

于是首页改成了 layout: doc——就是我手写 index.md 时写在最上面那一行。改成 doc 之后，整页交回给 Markdown，我在里面直接写 <HomeHero />，版式全在组件的 <style scoped> 里。

代价也清楚：导航栏的高亮会失效。默认主题靠页面的 frontmatter 判断当前在哪个栏目，一个手写的首页没有归属，所以顶栏哪个都不亮。我接受了这件事——首页本来就谁的栏目也不是。真要修，就得改主题的 Layout.vue，为一次高亮去改主题，不划算。

站内链接少了 withBase() 就会 404

这是我在 LinkCard.vue 上踩过的一个坑，写下来给后来的人省一个下午。

这个站部署在 yichen0808.github.io/Blog-pages/，也就是说 base 是 /Blog-pages/。Markdown 里的链接由 VitePress 在构建期处理，会自动带上这个前缀。但组件里自己拼出来的 href 不会——它是运行时的字符串，构建器看不见。

所以 LinkCard 里必须显式调 withBase()：

ts
import { withBase } from 'vitepress'

少这一步，写 /notes/lyric-scroll 得到的路径就是站点的根，而不是 /Blog-pages/ 下面，点进去是 404。

还有一层更细的：VitePress 默认 cleanUrls: false，产物是 novels/xuezhong.html。Markdown 里的链接会被自动补上 .html，但组件拼出来的不会，所以要照着 site.value.cleanUrls 自己补一次。

最后是 target 的取舍。站内链接不能加 target，因为 VitePress 的客户端路由靠一个挂在 window 上的点击拦截器工作，它要求同源、路径是 html、且 <a> 上没有 target。加了 target 就会被跳过，退化成整页刷新，白屏一下再回来。站外链接则相反，必须带上 target="_blank"，让拦截器主动放行。

.vp-doc 的那点特异性

组件写在 Markdown 里，就会落在 .vp-doc 这个容器内部，于是默认主题给它下面所有 <a> 加的链接色和下划线，也会落到卡片上。

处理办法是在组件自己的样式里直接压掉：

css
.link-card {
  color: var(--lc-ink);
  text-decoration: none;
}

这个选择器比默认主题的 a 更强，能赢。但同样是「谁赢」的问题，在别处就没这么轻松了：比如时间线那几条，.vp-doc h3 的特异性是 (0,1,1)，我写 .tl-item h3 只能打平，胜负取决于 CSS 的加载顺序。所以那些选择器一律带上 .timeline 前缀，变成 (0,2,1)——不赌顺序，比事后调试便宜。

小结

首页写成组件，得到的是完全的控制权，付出的是几处默认行为要自己接回来：导航高亮、base 前缀、.html 后缀、锚点样式。这些都不难，难的是不知道它们存在。所以我把每一条都写进了组件的注释里——半年后的我，就是那个不知道的人。
