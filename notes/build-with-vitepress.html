用 VitePress 搭一间自己的书斋

盖房子之前先想清楚要住多久，比选哪种砖更要紧。

上一篇里说过，上一间书斋停在三年前。这次重新动手，第一件事不是挑主题，是想明白上次为什么塌。

上一间是怎么塌的

旧站用的是 Hexo。它没有错，只是对我来说太重了：一次大版本升级之后，主题的模板语法跟着变了；本地 Node 的版本卡在某个区间里；换台机器就要重新配一遍环境。真正压垮它的是一件很小的事——某天我只想改一个错别字，结果花了四十分钟在装依赖。

一间书斋如果进门要先搬开一堆家具，那它迟早会被空着。

为什么是 VitePress

  • Hexo：生态老，插件多，但模板层和 Markdown 是两套语法，改版式等于改主题代码。我不想再学一遍主题怎么写。
  • Hugo：构建是真的快，Go 模板也是真的难读。我要改一处布局，得先回忆半天它的上下文变量从哪来。
  • Nextra：走的是 React 那一套，灵活，但对我来说是杀鸡用牛刀。为了写几百字，去维护一整个 Next 项目，不值。
  • VitePress：Markdown 是唯一的事实来源，构建交给 Vite，主题就是 Vue 组件。写文章和改版式用的是同一门手艺，这就够了。

vitepress 锁在 1.6.4。版本写死不是保守，是知道自己不会天天跟着升级走。

Markdown 是源，不是格式

这一点的好处要写过才体会得到。文章就是 docs 下面一个个 .md 文件，标题是 #，分段是空行，链接是方括号加圆括号。没有数据库，没有后台，没有「导出」这个动作。

想找三年前写过什么，直接翻文件夹。想改，打开编辑器。哪天不想用 VitePress 了，把 docs 打包带走，换任何工具都能读。

至于产物，npm run build 之后全在 docs/.vitepress/dist 里，是一堆静态 HTML、CSS 和 JS。GitHub Actions 那边也是把这个目录原样上传成 Pages 的产物，不需要额外的发布步骤。

三件我不要的东西

  • 不要评论。评论区是给人看的，但更多时候是给情绪看的。没有人留言，不代表没有人读过。
  • 不要统计。一旦能看到阅读量，就会忍不住去看，然后开始按数字写东西。
  • 不要广告。理由不必解释。

这三条听起来像是姿态，其实只是为了让这间书斋安静。安静是它可以被长期住下去的唯一条件。

一处顺手留下的缺口

base 写的是 /Blog-pages/，因为部署地址是 yichen0808.github.io/Blog-pages/。注意这里大小写不能改：GitHub Pages 的项目站点路径就是仓库名本身，而路径是大小写敏感的——写成小写的 blog_pages 之后首页照样打得开（index.html 由 Pages 直接给出），但所有 CSS、JS 和图片会一起 404。等哪天绑上自己的域名，把它改成 / 就行。

配置里还有一行 ignoreDeadLinks: true。那是我为了让站点先跑起来，对一批还没写的文章做的妥协。写完它们之后，这一行应该改回 false——让死链检查重新开始干活，比我自己记得哪些链接没写要可靠。

小结

框架选型到头来不复杂：挑一个「不想写的时候也能写」的。VitePress 对我来说就是那个——起一个 dev 服务器几秒钟的事，写不写是一回事，门槛先拆掉。
